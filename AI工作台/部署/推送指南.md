# 推送指南 · 把 AI 工作台放到 GitHub Pages

> 两条路，**默认走 A**。
> A = 现成的「GitHub 助手」CLI（令牌内置，不用自己造 token）。
> B = 本目录的 `deploy_github.py`，只在没有助手的机器上用。
>
> ⚠ **先说清楚**：放在 Pages 上的只是**界面和备份**。
> 真数据（TRAE 状态、员工名册、任务卡、原话）只在本机，
> 网页版必须连本机的 `http://127.0.0.1:19900` 才是能用的面板。
> Pages 那份打不开数据，只能看长什么样、当备份存档。

---

## A. 主流程（GitHub 助手 CLI，已实测可用）

工具（工作台下的开发资源包，名字/位置会变，别写死盘符）：

```
python "<开发资源包>\github助手\github助手含CLI.py" <命令>
```

下面统一写 `python`；若你机器上 `python` 是应用商店占位程序（报 9009 或弹商店），
换成真实解释器的完整路径即可，后面所有命令同理。

它有 9 个命令：`repos / files / dl-file / ul-file / dl-repo / ul-dir / rm-file / url / disk`。
**没有「新建仓库」**，所以用现成仓库：`FOXFYH/gittest`（公共试验仓，Pages 已开）。

### ① 造发布目录

本机建 `C:\Temp\_发布AI工作台\AI工作台\`，按原相对结构放这些文件：

| 放哪里 | 文件 |
|---|---|
| `AI工作台\` | `总管面板.pyw` `总管面板CLI.py` `核心.py` `采集器.py` `任务卡库.py` `任务执行器.py` `原话解析.py` `公共.py` `README.md` `.gitignore` `LICENSE` |
| `AI工作台\网页端源文件\` | `AI工作台.html`（= 本机 `总管面板.html` 的副本，只改文件名） |
| `AI工作台\部署\` | `deploy_github.py` `脱敏审计.py` `推送指南.md` |

**不进仓库**：`设计_v0.x.md`、`员工名册_来源说明.md`、`自测报告.md`、`验收*`、`回执*`、
`手册\`、`配置.json`、`状态.json`、`员工名册.json`、`任务卡.json`、`原话备注.json`、
`_tmp_*`、`__pycache__`、`日志\`、`备份\`。
理由：内部设计稿、名册说明、作业手册里含本机痕迹路径与员工真名，脱敏后就没查阅价值，不如留在本机。

**频道号与首次密码同样不入库**：它们只活在 `配置.json`（已被 `.gitignore` 忽略）。
README 只说「首次登录需输入频道号，见随附说明」，不写具体串；
写进代码/文档就会被 `脱敏审计.py` 判 DIRTY 并拦下上传。

### ② 对发布目录跑脱敏审计（必须 CLEAN）

```
python 部署\脱敏审计.py --路径 C:\Temp\_发布AI工作台
```

必须是 `RESULT=CLEAN`。不是 CLEAN 就停下，把命中行贴给负责人，**不许传**。

### ③ 试运行（只对比，不提交）

```
python "<开发资源包>\github助手\github助手含CLI.py" ul-dir FOXFYH/gittest C:\Temp\_发布AI工作台 --dry
```

期望：**新增 15~17，更新 0，删除 0**。
出现「更新」或「删除」就停——说明远端已有同名文件被人改过，或本地目录指错了。

### ④ 真传（去掉 `--dry`）

```
python "<开发资源包>\github助手\github助手含CLI.py" ul-dir FOXFYH/gittest C:\Temp\_发布AI工作台
```

**绝不加 `--delete`**：那会把 gittest 里别人的页面一起删掉（比如 `任务面板/`）。
成功后它会打印一行 `提交: <URL>`，记下来。

### ⑤ 拿 Pages 地址

```
python "<开发资源包>\github助手\github助手含CLI.py" url FOXFYH/gittest "AI工作台/网页端源文件/AI工作台.html"
```

输出形如 `https://foxfyh.github.io/gittest/...`。
Pages 生效要 1~3 分钟，期间 404 属正常，别反复重传
（`ul-dir` 按内容指纹跳过未变文件，重跑不会重复提交）。

## B. 备用：deploy_github.py（没有助手的机器）

**仅在没有 GitHub 助手的环境用。** 它不依赖 git/gh，全程走 GitHub REST API。

1. 生成 PAT：GitHub → 头像 → Settings → Developer settings →
   Personal access tokens → **Tokens (classic)** → Generate new token，勾 **repo**。
2. PowerShell 设环境变量：`$env:GH_TOKEN = "ghp_xxxx"`
3. 试运行（不需要令牌，只列清单）：`python 部署\deploy_github.py --试运行`
4. 真推：`python 部署\deploy_github.py --账号 你的用户名`（默认私有仓库）
5. 它会自己建仓 → 跑脱敏审计（不 CLEAN 直接拒绝）→ 逐个上传 → 开 Pages
6. 失败会打印 HTTP 状态码 + 返回体原文（截 500 字）

| 状态码 | 意思 | 怎么办 |
|---|---|---|
| 401 | 令牌无效/过期/带空格 | 重新生成并重设 `GH_TOKEN` |
| 403 | 没勾 `repo` | 重新生成令牌勾满 repo |
| 404 | 账号拼错，或令牌看不到该私有仓库 | 检查 `--账号` |
| 409 | Pages 已经开过（**不算错**） | 脚本会自动改 PUT 更新 |
| 422 | 仓库重名 / 空仓库首次误带 branch | 换 `--仓库`；首次上传脚本已自动不带 |

## 附：令牌泄露了怎么办

GitHub → Settings → Developer settings → Tokens (classic) → 找到那条 → **Delete**，
重新生成一条。令牌只是门钥匙，已推上去的内容不受影响。
任何令牌都不许写进文件、不进仓库、不贴聊天。
